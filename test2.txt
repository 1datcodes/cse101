Sorting:
  Selection sort:
    Best, worst, and average case of O(n^2) since inner loop runs the whole span of the array regardless of the value.
    Number of swaps is at most n-1 (one per pass);

  Insertion sort:
    Best case O(n), Worst case O(n^2), and average case O(n^2)
    Number of shifts equals the number of inversions. A sorted array has 0 inversions; a reversed array has the max of n(n-1)/2 inversions.

Practice 1:

    - {2, 5, 9, 8, 6} 4 comparisons
    - {2, 5, 9, 8, 6} 3 comparisons
    - {2, 5, 6, 8, 9} 2 comparisons
    - {2, 5, 6, 8, 9} 1 comparisons
    - sorted! 10 comparisons total, 2 swaps total.
  2: How many comparisons does selection sort make on a sorted array of 8 elements? On a reversed array of 8 elements?
    - Number of comparisons depends entirely on n and not on the data. Both cases selection sort will compare n(n-1)/2 times or 28.
  3: Run insertion sort on {2, 3, 1}. How many shifts happen? How many inversions does the array have?
    - {2, 3, 1} no shifts
    - {1, 2, 3} 2 shifts
    - array has 2 inversions (3, 1) and (2, 1)
  4: Give and input of size n=6 that is a worst case for insertion sort and state the total number of shifts.
    - {6, 5, 4, 3, 2, 1}
    - number of shifts would equal n(n-1)/2 which is 15
  5: Count how many times count++ executes, as a function of n, and give O()
    ``
    for (int i = 0; i < n; i++) {
        for (int j = i; j < n; j++) {
            count++;
        }
    }
    ``
    - count++ will run n(n-1)/2 times which means time complexity of O(n^2)

  6: Why is the number of comparisons fixed for selection sort but variable for insertion sort?
    - because selection sort must span the entire unsorted array for the minimum, but insertion sort only needs to find the correct position for the key.

Binary Search:
  Divide and conquer search algorithm. Relies on a sorted array to work.
  Time complexity:
    Each call does at most 2 comparisons and one computation. Each recursive call works on about half of the range: n/2, n/4, n/8... until 1 element remains.
    Therefore the total runtime is about Log_2(n) or O(logn) time in the worst case. Best case it is O(1) when the key is exactly at the half point of the array.
    O(logn) means doubling the array would mean adding only one more probe meaning this search works best with data that scales fast.
    Max Runtime: log_2(n) + 1

Priority Queues:
  A priority queue stores items with priorities and always gives access to the item of highest priority. (larger key = higher priority, max-priority queue)
  Operations:
    insert(x): adds item x to the queue.
    findMax(): returns the largest item without removing it.
    extractMax(): removes and returns the largest item.
  Same ADT can be implemented in different ways and the choice decides which operations are cheap

  Comparing implementations:
    Unsorted Array:
      insert - O(1) (append)
      findMax - O(n)
      extractMax - O(n)
    Sorted array (max at end):
      insert - O(n) (shift)
      findMax - O(1)
      extractMax - O(1)
    Unserted linked list:
      insert - O(1) (at head)
      findMax - O(n)
      extractMac - O(n)
    Sorted linked list (max at head):
      insert - O(n) (walk to position)
      findMax - O(1)
      extractMax - O(1)
    Binary heap:
      insert - O(logn)
      findMax - O(1)
      extractMax - O(logn)
  
Practice 3:
  1: A PQ is implemented with a sorted linked list with the maximum at the head. Give the worst-case time of findMax, insert, and extractMax, with a reason for each.
    - insert: O(n), key is less than all the elements in the PQ, which means insert must walk to the end of the linked list to append
    - findMax: O(1), since PQ is sorted with max at the head, accessing max takes O(1) time
    - extractMax: O(1), same as above; linking the head to the second element also takes constant time
  2: Fill in the worst-case time for an unsorted array PQ and binary heap PQ: (a) insert, (b) findMax, (c) extractMax
    (a) O(1) for unsorted array, O(logn) for binary heap
    (b) O(n) for unsorted array, O(1) for binary heap
    (c) O(n) for unsorted array, O(logn) for binary heap

Binary Max Heap:
  A binary tree that satisfies two invariants at all times:
  - Shape property: it is a complete binary tree: every level is full except possibly the last, and the last level is filled from the left with no gaps
  - Heap-order property: every node's key is >= the keys of its children. So the maximum is always at the root
  * a heap does not order the left child against the right child, so you cannot search it quickly. It is only ordered along each root-to-leaf path.
