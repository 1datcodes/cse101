Sorting:
  Selection sort:
    Best, worst, and average case of O(n^2) since inner loop runs the whole span of the array regardless of the value.
    Number of swaps is at most n-1 (one per pass);

  Insertion sort:
    Best case O(n), Worst case O(n^2), and average case O(n^2)
    Number of shifts equals the number of inversions. A sorted array has 0 inversions; a reversed array has the max of n(n-1)/2 inversions.

Binary Search:
  Divide and conquer search algorithm. Relies on a sorted array to work.
  Time complexity:
    Each call does at most 2 comparisons and one computation. Each recursive call works on about half of the range: n/2, n/4, n/8... until 1 element remains.
    Therefore the total runtime is about Log_2(n) or O(logn) time in the worst case. Best case it is O(1) when the key is exactly at the half point of the array.
    O(logn) means doubling the array would mean adding only one more probe meaning this search works best with data that scales fast.
    Max Runtime: log_2(n) + 1

Priority Queues:
  A priority queue stores items with priorities and always gives access to the item of highest priority. (larger key = higher priority, max-priority queue)
  Operations:
    insert(x): adds item x to the queue.
    findMax(): returns the largest item without removing it.
    extractMax(): removes and returns the largest item.
  Same ADT can be implemented in different ways and the choice decides which operations are cheap

  Comparing implementations:
    Unsorted Array:
      insert - O(1) (append)
      findMax - O(n)
      extractMax - O(n)
    Sorted array (max at end):
      insert - O(n) (shift)
      findMax - O(1)
      extractMax - O(1)
    Unserted linked list:
      insert - O(1) (at head)
      findMax - O(n)
      extractMac - O(n)
    Sorted linked list (max at head):
      insert - O(n) (walk to position)
      findMax - O(1)
      extractMax - O(1)
    Binary heap:
      insert - O(logn)
      findMax - O(1)
      extractMax - O(logn)

Binary Max Heap:
  A binary tree that satisfies two invariants at all times:
  - Shape property: it is a complete binary tree: every level is full except possibly the last, and the last level is filled from the left with no gaps
  - Heap-order property: every node's key is >= the keys of its children. So the maximum is always at the root
  * a heap does not order the left child against the right child, so you cannot search it quickly. It is only ordered along each root-to-leaf path.

  Implementations:
    Array implementations
      - Because the tree is complete there are no gaps, so we can store it by level in an array, with no pointers. We leave a[0] unused so that the index formulas are simple.
      - Formulas
        - Parent: i/2 (integer division), valid when i > 1 (the root has no parent)
        - Left child: 2 * i, valid when 2i <= n
        - Right child: 2 * i + 1, valid when 2i + 1 <= n
    Time complexity:
      - findMax: read a[1], O(1) time
      - insert: swim climbs at most the height log_2(n), O(logn) worst case, O(1) if the new key is small
      - extractMax: sink descends at most log_2(n), O(logn)

BuildHeap and Heapsort:
  BuildHeap: building a heap from an array
    Given an unordered array a[1...n], we want to rearrange it in place into a max-heap.
    Two natural ways:
      - Bottom-up with sink (standard heapify)
        ``
        void buildHeap() { // a[1...n] holds arbitrary data
            for (int i = n; i >= 1; i--) { // from the last node up to the root
                sink(i);
              }
        }
        ``
      - Top-down with swim (repeated insertion)
        ``
        void buildHeap() { // "insert" a[1...n] one by one
            for (int i = 1; i <= n; i++) {
                swim(i);
            }
        }
        ``
      * Heaps built from the same data are not unique -> different implementations can yield different results
    Analysis of buildHeap:
      - Bottom-up (sink): O(n)
        sink(i) consts at most the height of node i (how far it can fall). Most nodes are near the bottom and have a small height.
        In general there are at most n/2^(h+1) nodes of height h, so the total work is at most sum(h*n/2^(h+1)) = (n/2)*sum(h/2^h)<=(n/2)*2=n. Half the nodes do no work, a quarter do at most 1 step, an eight at most 2, etc. The total is O(n) for worst and average case.
      - Top-down (swim): O(nlogn)
        A node at depth d can swim up at most d levels. Most nodes are near the bottom, so they have the largest depth.
        About n/2 nodes sit at depth~log_2(n), so the worst case (data already in increasing order) costs about (n/2)*log_2(n) swaps: O(nlogn)
      * The difference comes from the triangular structure of binary heap where most nodes lives near the bottom.
      ** Rule of thumb: when building from a whole array, use sink O(n). When items arrive one at a time, use swim O(logn) each.

  Heapsort:
    Idea: build a max-heap, then repeatedly take the maximum and put it at the end. After each extraction the heap is one element smaller, so the freed slot at the end holds the extracted maximum, and the array fills up with the sorted output from the back.
    Ex:
      start     16 4 10 2 1 9 3 |       heap built
      1         10 4 9 2 1 3 | 16       16 to the end; 3 sinks past 10, then 9
      2         9 4 3 2 1 | 10 16       10 to the end; 4 sinks past 9
      3         4 2 3 1 | 9 10 16       9 to the end; 1 sinks past 4, then 2
      4         3 2 1 | 4 9 10 16       4 to the end
      5         2 1 | 3 4 9 10 16       3 to the end
      6         1 | 2 3 4 9 10 16       2 to the end; sorted
    
    Time complexity:
      Phase 1: build
        O(n), from the buildHeap analysis
      Phase 2:
        n - 1 rounds; each does one O(1) swap and one sink of cost O(logn). The total is at most O(nlogn). Simple bound: (n-1)*logn
      Total: O(nlogn) in the worst case, which is much better than the O(n^2) of selection and insertion sort in the worst case

Binary Tree:
  A tree sorts data in nodes connected by edges. One special node, root, sits at the top and every other node hangs below exactly one parent.
  In a binary tree every node has at most two children, called left child and right child.
  Trees are naturally recursive: each child is the root of a smaller tree (a subtree). This is why most tree algorithms are written recursively.

  Terms:
    Root: The topmost node; the only node with no parent
    Parent/child: a node directly above/directly below another node
    Siblings: Nodes that share the same parent
    Leaf: A node with no children
    Internal Node: a node with at least one child
    Ancestor: a node on the path from a node up to the root
    Descendant: a node below a node
    Subtree: a node together with all of its descendants. The left subtree and right subtree of a node are the subtrees rooted at its children
    Depth of a node: Number of edges on the path from the root to the node
    Height of a node: Number of edges on the longest downward path from the node to a leaf
    Height of a tree: the height of its root
    Level: All nodes at the same depth
