Tree Traversal:
  - Preorder:
    Node, Left, Right: The node comes before the subtrees. The first node printed is always the root.
  - Postorder:
    Left, Right, Node: The node comes after the subtrees. The last node printed is always the root.
  - Inorder:
    Left, Node, Right: The node comes in between the subtrees. It will be printed in sorted order.
  Time complexity:
    Since all functions traverse the entire tree, each function is in O(n) time.
Tree reconstruction:
  Inorder alone is not enough information to reconstruct the BST since there are multiple permutations of trees with the same sorted output
  Preorder alone is enough information to reconstruct the BST
    Since preorder prints root first, left subtree, then right subtree, we can compare with the root to determine which subtree a node belongs in.
  Postorder alone is also enough

AVL Trees:
  BST operations all cost O(h) but unbalanced trees means h=n for worst case scenario. (i.e. O(n))
  Self balancing trees guarantee average case O(h) (O(logn)) time
  Invariant:
    Difference between the heights of the left and right subtrees are no more than -1 to 1
    Every node of the tree follows above invariant
  It allows a small amount of lopsidedness which makes maintaining the tree fairly cheap
  Nodes increase exponentially with every level -> O(h)=O(logn)
  Rotations:
    Constant time local rearrangement that restores balance: O(1)
    Transfers the height from one side to the other
    Preserves the BST order of the tree
  4 imbalance cases:
    RR: one left rotation
    LL: one right rotation
    RL: right rotation at y, then left rotation at z
    LR: left rotation at y, then right rotation at z
    Rebalance function handles all 4 cases
  Find works the same way as BST, guaranteed O(logn) due to auto-balancing
  Insert:
    insert like regular BST, then on the way back up the recursion, repair every ancestor with rebalance
  Delete:
    delete like regular BST, then repair every ancestor on the way back
  AVL Tree costs:
    Find: O(logn)
    Insert: O(logn)
    Delete: O(logn)
    Rotation: O(1)
    Build from n keys: O(nlogn)
    Inorder traversal: O(n)

    ``
    int check(Node* n) {
        if (n == NULL) return -1;
        int l = check(n->left);
        if (l == -2) return -2;
        int r = check(n->right);
        if (r == -2) return -2;
        if (abs(l - r) > 1) return -2;
        return 1 + max(l, r);
      }
    bool is_avl(Node* root) {
        return check(root) != -2;
      }
    ``

Range counting in AVL tree
  One-ended range: how many keys are <= x (or >=, >, <)
  Both-ended range: how many keys are in [a, b]
  Standard way is to walk through and count which is O(k) where k<=n.
  We can do O(log n) if nodes remembered how many nodes are in its subtree
  - One-ended range: count keys <= x
    At each node, compare x with the node key
    - x < key: the node and everything in its right subtree are larger than x, so none of them counts; continue only on left subtree
    - x >= key: the node counts, and so does everything in its left subtree (all smaller than node) -> 1 + size_of(node->left) keys, added in O(1). Then continue on the right subtree for the rest
    Complexity:
      Every call makes at most one recursive call, and each does O(1) work -> function follows a signle root-to-leaf path which means at most h + 1 calls == O(logn)
  - Both-ended range: count the keys in [a, b]
    We do not need a new algorithm. The keys in [a, b] are the keys <= b minus keys < a
    Complexity:
      Two one-ended queries each on O(logn) time -> O(logn) time
